# 可复现实验与回放

第三阶段提供独立的规则仿真实验入口。离线实验与在线现场共用 `simulator.advance` 的运动、任务和穿越互锁逻辑；在线 `tick` 在推进后另行保存数据库。离线不启动 API、不读写现场数据库，不需要 GPU。

新增完整航空器运动、可替换初始车队、45 次配对敏感性实验与看板统计见 [航空器运行与对照实验](aircraft-and-studies.md)。原场景仍可运行；新策略版本为 `rules-v3-aircraft`，比较历史批次时还应核对 manifest 中的源码哈希。

## 云服务器运行

推荐 Python 3.11/3.12。在独立平台仓库运行：

```bash
git clone git@github.com:Draymond0504/arponviz.git
cd arponviz
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements-experiments.txt
python -m apronops.experiments.run \
  --scenario configs/experiments/routing.yaml \
  --seeds 1 2 3 \
  --policies priority_distance deadline_forecast rolling_optimization \
  --output results/experiments/routing-batch-001
```

把场景改为 `configs/experiments/turnaround.yaml` 可运行航班保障、预测误差和通信故障实验。每次选择新的输出目录，已有目录会被拒绝，防止覆盖结果。输出目录被 Git 忽略；更新代码使用 `git pull --ff-only`，另行归档实验目录。这里是规则策略的评估入口；模型训练仍属后续研究工作。

滚动优化无需额外求解器依赖。仅实验需要 Pydantic 和 PyYAML；看板、API 和测试使用完整 `requirements.txt`。目前批量任务串行运行，按场景、种子、策略生成子目录；没有断点续跑或分布式训练功能。

## 场景与时钟

场景格式版本为 1，严格校验未知字段和引用。`start_time` 显式配置时必须带时区，内部统一为 UTC；默认固定为 2026-01-01 00:00:00 UTC。所有 `*_s` 时间均相对场景起点。`horizon_s` 是观测终点，`step_s` 最大为 0.5 秒，时钟精度为微秒。外部事件、任务释放及飞机申请边界会拆分步长，不会直接跳过短窗口。

- `flights`：航班公布时刻、机位、到达时刻与扰动幅度、周转时长；模板生成行李、配餐、保障后检查及依赖。
- `tasks`：直接任务、类型、起终点、释放/截止时间、优先级、服务时长。
- `crossings`：交叉点、飞机标识、公布时刻、预测窗口、申请偏移与扰动幅度。实际授予必须等冲突区清空。
- `closures`：路段双向封闭与计划重开。
- `faults`：通信或定位故障，以及计划修复。

同一道路或同车同类故障的重叠/相接恢复区间会被拒绝，避免共享告警的恢复歧义。车辆初始配置读取 `data/vehicles_seed.yaml`，路网读取独立车辆道路及 Layout H 参照；实验清空在线演示种子任务。修改这些数据应和场景一起版本管理。

场景先用独立随机源生成实际输入，再交给策略。相同配置、种子、代码及依赖环境下，事件日志、采样轨迹、任务表和指标应一致。`inputs.json` 保存应用零时刻事件之前的初始世界；计算输入哈希时只排除策略名。批量比较检查同一种子的各策略输入哈希一致。

## 规则基线与滚动优化

| 策略 | 任务顺序与选车 | 寻路 |
|---|---|---|
| `priority_distance` | 优先级顺序，兼容空闲车辆中取货距离最近 | 排除封路后的最短距离 |
| `deadline_forecast` | 截止时间顺序，兼容空闲车辆中预计完成时间最早，计入基地队列 | 结合车辆速度、道路限速与公开穿越预测窗口的时间依赖路径；在节点重新规划 |
| `rolling_optimization` | 每 15 秒有界联合匹配，计入延误、延期分配与基地办理压力 | 同预测路径 |

预测策略只用已公布的预测窗口和当前已授予的占用信息，不读取未来申请窗口或未来故障。预测只影响规划，实际停车仍由统一互锁决定。预计完成时间包含当前基地队列、办理和服务时长，但没有完整模拟加减速与沿路前车排队。基地预留和恢复是所有策略共用的约束，预测规则不能保证比最近车辆规则更好。

当前策略版本为 `rules-v3-aircraft`，新增 `rolling_optimization`、基地容量和排队预测，详见 [基地与滚动优化](depots-and-optimization.md)。未接入学习策略。

## 输出与指标

每个运行子目录包含：

| 文件 | 内容 |
|---|---|
| `manifest.json` | 场景配置、策略版本、种子、输入哈希、Git 提交/工作树状态、源码哈希、依赖版本、运行状态和错误 |
| `inputs.json` / `layout.json` | 实际输入事件、初始世界、独立路网与飞机参照 |
| `events.jsonl` | 全部调度、规划、等待/恢复、故障、任务及穿越事件 |
| `frames.jsonl` | 初始帧、采样帧、终点帧，含车辆、任务、交叉区和封路状态 |
| `tasks.csv` | 任务释放、截止、开始/完成时刻及最终状态 |
| `summary.json` | 整次运行指标 |
| `performance.json` | 墙钟耗时与策略调用耗时，单独保存，不参与确定性比较 |
| `replay.json` | 可搬运到本机的完整回放，含配置、路网、采样帧及汇总 |

批次根目录的 `comparison.csv` 汇总成功跑到观测终点的各次运行。`completed` 表示运行到达观测终点，**不表示所有任务完成**。Ctrl+C 的当前运行标为 `interrupted`，运行异常标为 `failed`，保存已产生的日志、末帧及部分指标；CLI 分别返回 130 和 1。中断/失败运行不会伪装成完整比较行，应检查它们各自的 manifest/summary。配置校验失败发生在创建运行目录之前。

`sample_s` 指定采样间隔（默认 5 秒）；若与步长不整除，采样发生在跨过采样边界的第一个步长终点。每帧保存自身时间，初始帧和最终帧总会保留。动画采样不是每次物理子步，互锁违规检查在物理子步执行。

| 指标 | 定义 |
|---|---|
| `completion_rate` | 已完成 / 截至停止时已释放任务；没有已释放任务时为 null |
| `due_on_time_rate` | 按时完成 / 截至停止时已到期的已释放任务 |
| `tardiness_lower_bound_s` | 已到期任务累计延误；未完成任务用停止时刻计算下界，不按零处理 |
| `completed_tardiness_p95_s` | 仅已完成任务延误的最近秩 p95；必须配合未完成数阅读 |
| `distance_m` / `empty_distance_m` | 累积行驶米数 / 取货前与返程的米数 |
| `route_wait_s` | 路径、交叉或前车阻挡等待的累计车辆秒；多个车辆同时等待分别累计 |
| `crossing_wait_s` / `traffic_wait_s` | 上述等待中由飞机/交叉区、前方车辆造成的部分；故障暂停时间不重复计入 |
| `conflict_zone_violation_steps` | 每个子步检测到空地重叠、多个飞机或多个车辆同时占用的冲突区次数 |
| `aircraft_grant_delay_s` | 已授予请求相对申请起点的累计延迟 |
| `aircraft_ungranted_requests` | 已到申请起点、截至停止仍未获准的请求数量 |

等待时长按物理子步末尾的原因累计，是离散近似。零冲突计数仅对应模型内这些图冲突区检查，不代表车道级或真实机场安全验证。

## 看板回放

启动看板后选择“实验回放”，从本机结果列表选择运行，或上传云服务器生成的 `replay.json`。文件大小限制为 100 MB，上传内容仅按 JSON 读取并验证，不执行代码。页面不调用现场 API，因此即使 API 离线也可查看回放；初始“运行总览”可能提示 API 不可用，切换页面即可。

默认扫描 `results/experiments` 下的一层或两层运行目录。可用 `APRONOPS_RESULTS_DIR` 指向下载目录。Docker 用户可直接上传文件；若要扫描宿主目录，需自行挂载对应目录并设置此环境变量。

时间轴显示当帧的地图、车辆等待原因、任务、封路和飞机管制；“整次实验汇总”始终显示截至停止时刻的最终指标。逐帧轨迹尾迹最多取前 80 个采样帧。

页面上方提供完整动画播放器：播放/暂停、1–120 倍速、拖动进度、从头播放、关键时刻跳转、缩放平移和车辆选择。默认 60 倍速，80 分钟仿真约 80 秒播完；切到后台自动暂停。动画右侧同步显示任务、基地和管制状态。下方逐帧滑块独立于动画，用于详细数据核对。

点击“下载完整动画（HTML，离线打开）”获得包含数据与播放器的单个 HTML，无需 API 或外部网络即可打开。也可通过命令行导出，输出文件必须不存在：

```bash
python -m apronops.dashboard.replay_player \
  results/experiments/acceptance-shift-001/acceptance_shift-rolling_optimization-seed1/replay.json \
  --output results/experiments/acceptance-shift-001/acceptance-animation.html
```

默认不在车辆旁堆叠全部车名；悬停列出附近车辆，点击密集位置可轮换选择，或直接下拉选车。选中车辆显示引线与轨迹，真实坐标不移动。地图可滚轮缩放、拖动平移或适应全图。运行总览也采用悬停名称和最多三辆高亮引线标签。

动画仅在前后采样处于同一记录路段时插值位置，跨路段则保留采样位置到下一帧，不绘制跨弯道直线捷径。任务、故障、封路与穿越状态按采样更新，不能用插值画面检查物理子步的互锁安全；精确事实仍以事件和子步指标为准。

## 第三阶段历史验收结果（旧版本）

以下结果属于旧版 `rules-v1`，不代表当前泊位模型表现。两份合成场景分别以种子 1、2、3 比较两种规则，共 12 次运行。`routing`（1800 秒）中最近距离规则每次完成 3/3，预测规则每次完成 2/3；`turnaround`（2400 秒）分别为 4/6 与 3/6。全部运行的图冲突区违规计数为 0。这些结果用于验收工程链路，不是算法优越性或论文统计结论。

`routing` 中，预计到达更快的 SHUTTLE_01 被派往 DEPOT_AMR 取货，停驻于该节点的 AMR_INSPECT_01 阻挡了入口。回放记录“前方车辆阻挡”，回归测试验证移除实际阻挡后任务能够开始。该结果暴露了忽略基地排队的预计到达模型缺陷；没有改动输入来让预测规则取得更好的结果。`turnaround` 还存在观测终点时配餐未结束、检查任务等待前置保障完成的情况。

第四阶段已加入基地泊位、排队预测、有限恢复规则及滚动联合分配。新配置、新约束下应重新运行各策略，不能把旧版数据当作当前结果。详见 [基地与滚动优化](depots-and-optimization.md)。
