# 运行与异常处置

第一阶段版本提供可以恢复的仿真任务闭环，默认数据库为 `apronops-operations-v1.db`。API、调度和仿真仍由单进程运行，启动时保持一个 uvicorn worker；多实例共同调度尚未实现。

## 在看板上操作

运行总览每 2 秒刷新车辆、任务、轨迹与封路状态；仿真每 2 秒墙钟时间推进 5 秒。时间旁显示状态版本。创建任务表单位于定时刷新区域之外；任务 ID 唯一，重复创建返回冲突，便于避免重复工单。

异常处置页支持通信中断、定位质量下降，以及选择具体道路进行双向封闭。封闭道路在地图上显示红色虚线。选择对应告警并填写说明，即可确认恢复；处置记录和任务事件可在同页查看。看板从后端获取完整状态快照，不再依赖浏览器直接连接后端 WebSocket，因此 Docker 内部的 `api` 主机名不需要浏览器解析。原有 WebSocket 接口仍提供状态通知。

道路变化、车辆恢复、任务创建在响应成功前写入数据库。后台推进失败时暂停运行，并在状态与 `/health` 中报告，避免把停止的画面当成正常运行。

## 任务转派与车辆恢复

| 发生故障时的阶段 | 当前处理 |
|---|---|
| 空闲 | 停止调度，故障全部解决后恢复空闲 |
| 前往任务起点，尚未取货 | 通信中断时任务进入待转派队列；同类型空闲车按可达距离重新分配；原车恢复后返回基地 |
| 前往任务终点，已经取货 | 保留原车任务，故障解除后从原位置继续；不自动进行物理货物交接 |
| 正在服务 | 保留剩余服务时长，解除故障后继续倒计时 |
| 返回基地 | 保留返程状态，修复后完成返程 |

定位质量下降会暂停原车任务，修复后续跑。同车若有多个未解决故障，解决其中一个不会提前放行。已经转派的任务不会重新绑定回原车。原车故障发生在路段中部时，恢复后先走完当前可通行路段，再规划返回基地，不重置坐标。

## 道路封闭

关闭一个路段会使双向最短路都排除这条边，并使既有路径缓存失效。

- 尚未驶入封闭边：从当前节点重新寻路。
- 已驶入封闭边：保留位置并停车，等待道路恢复。当前模型不模拟倒车与撤离。
- 到目标完全不可达：保留任务与车辆阶段，记录等待原因，不让整个仿真循环报错。
- 尚未分配且起终点不连通的任务：保留在队列中，路网恢复后再分配。

道路告警与实际封闭状态绑定；关闭告警会同步开放道路，直接重开道路也会关闭对应告警。重复关闭同一条仍封闭的边返回已有记录，重复恢复不会新增事件或覆盖原处置说明。

默认在线策略仍按距离最短；离线实验可选择公开穿越预测策略，见 [实验与回放](experiments.md)。第二阶段已取消交叉节点固定 3 秒停车，改为图上停止线前等待和模拟空地互锁，详见 [航班与穿越](flights-and-crossings.md)。

## 快照与数据库

快照与车辆、任务、事件、告警在同一 SQLite 事务内提交，包含：车辆路段进度、计划路径、任务阶段、服务剩余时长、基地映射、故障恢复状态、封路记录、交叉等待、轨迹尾迹、仿真时间及状态版本。当前快照版本 4 还保存随机源状态、事件计数、策略名与累计里程，并兼容读取版本 1/2/3。

正常重启或意外退出后，使用相同 `APRONOPS_DB_PATH` 会恢复最后成功提交的状态。停机期间仿真时间不推进；进程崩溃时，未提交的当前一步不计入恢复状态。

启动时检查道路指纹。拓扑不匹配、快照版本不支持、或数据库只有旧版记录而缺少完整快照时，启动会明确失败并保留数据。可指定另一个数据库开始新场景：

```bash
APRONOPS_DB_PATH=apronops-operations-v1.db uvicorn apronops.api.main:app --host 127.0.0.1 --port 8000
```

原来的 `apronops.db`、`apronops-layout-h.db`、`apronops-vehicle-h-v1.db` 保留。Docker 使用 `/app/runtime/apronops-operations-v1.db`，旧卷中的历史文件仍保留。已有快照时，车辆和任务种子配置不会覆盖现场；要以新种子开始场景，使用新数据库。

当前保存的是最新运行快照与有限轨迹尾迹，尚不等同于完整历史轨迹回放或实验检查点。API 仍用于本地仿真，身份认证和用户级审计待后续应用部署阶段补充。

## 接口

| 接口 | 用途 |
|---|---|
| `GET /state` | 同一锁内读取时间、状态版本、车辆、任务、告警、封路、轨迹和等待原因 |
| `GET /health` | 推进正常返回 200；推进失败暂停后返回 503 |
| `POST /tasks` | 创建并持久化任务；优先级 1–5，截止时间偏移为正数 |
| `POST /anomalies/inject` | 注入车辆故障；原 `route_blocked` 参数会封闭车辆当前或下一路段，无有效路段时拒绝 |
| `POST /roads/closures` | `{from_node, to_node, reason}` 封闭真实存在的双向边 |
| `GET /roads/closures` | 封闭与恢复记录 |
| `POST /roads/closures/{id}/reopen` | `{resolution}` 重开道路并解决关联告警 |
| `POST /alerts/{id}/resolve` | `{resolution}` 解决故障或重开道路 |
| `GET /routes` | 基于当前开放路网寻路，无路线返回 409 |
| `GET /events?task_id=...` | 查询创建、分配、转派、服务、完成、道路及处置事件 |

API 写入失败会回滚内存中的操作，并返回错误；后台一步推进写入失败也会回滚该步内存并暂停。默认 API 关闭随机异常注入，异常由显式操作触发。

## 指标口径

`on_time_rate`：到统计时刻已到截止时间的任务中，按时完成的任务比例。逾期未完成任务保留在分母。暂无到期任务时看板显示“暂无到期任务”。`completed_on_time_rate` 保留“已完成任务中的按时比例”供区分。

`alert_resolution_rate`：已解决告警 / 全部告警。移除了名称误导的 `manual_intervention_rate` 字段，不将告警关闭解释成人工介入率。`overdue_unfinished` 显示已到截止时间仍未完成的任务数量（含失败任务）。其他平均时长目前仍按已有已完成任务计算。
